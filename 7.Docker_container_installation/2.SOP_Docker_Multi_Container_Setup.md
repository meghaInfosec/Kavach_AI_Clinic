# SOP: Docker Installation and Multi-Container Lab Setup (Kali Linux)

**Document type:** Standard Operating Procedure
**Scope:** Installing Docker Engine on Kali Linux and deploying a three-container vulnerable-application lab (DVWA, Juice Shop, and a dedicated database container) using Docker Compose
**Environment:** Kali Linux (VirtualBox VM), non-root user `kali`

---

## 1. Purpose

This procedure documents the steps to:

1. Install Docker Engine on Kali Linux
2. Deploy three containers for a security-testing lab:
   - **DVWA** (Damn Vulnerable Web Application)
   - **Juice Shop** (OWASP Juice Shop)
   - **Database** (MariaDB, backing DVWA)
3. Define and manage these containers using a single Docker Compose (`.yml`) file

---

| Requirement | Detail |
|---|---|
| Operating system | Kali Linux (up to date) |
| User privileges | `sudo` access |

## 3. Procedure — Installing Docker Engine

### Step 3.1 — Update package index

```bash
sudo apt update
```

### Step 3.2 — Install prerequisite packages

```bash
sudo apt install -y ca-certificates curl gnupg lsb-release
```

### Step 3.3 — Install Docker

Kali Linux includes Docker in its own repositories, which is the simplest installation path:

```bash
sudo apt install -y docker.io
```

### Step 3.4 — Enable and start the Docker service

```bash
sudo systemctl enable docker
sudo systemctl start docker
```

### Step 3.5 — Verify installation

```bash
docker --version
sudo systemctl status docker
```

Expected: a version string (e.g. `Docker version 27.x.x`) and an `active (running)` service status.

### Step 3.6 — Allow the non-root user to run Docker (optional but recommended)

```bash
sudo usermod -aG docker $USER
```

Log out and log back in (or restart the terminal session) for the group change to take effect. After this, `docker` commands can be run without `sudo`.

### Step 3.7 — Install Docker Compose (if not bundled)

Check first:
```bash
docker compose version
```

If not found, install the plugin:
```bash
sudo apt install -y docker-compose-plugin
```

## 5. Docker Compose Configuration

Paste the following into `docker-compose.yml`:

```yaml
version: "3.8"

services:
  dvwa:
    image: ghcr.io/digininja/dvwa:latest
    container_name: dvwa
    restart: unless-stopped
    ports:
      - "8082:80"
    depends_on:
      - dvwa-db
    environment:
      - DB_SERVER=dvwa-db
    networks:
      - lab-network

  dvwa-db:
    image: mariadb:10.6
    container_name: dvwa-db
    restart: unless-stopped
    environment:
      - MYSQL_ROOT_PASSWORD=dvwa
      - MYSQL_DATABASE=dvwa
      - MYSQL_USER=dvwa
      - MYSQL_PASSWORD=p@ssw0rd
    networks:
      - lab-network

  juice-shop:
    image: bkimminich/juice-shop
    container_name: juice-shop
    restart: unless-stopped
    ports:
      - "3000:3000"
    networks:
      - lab-network

networks:
  lab-network:
    driver: bridge
```

### Configuration notes

| Field | Purpose |
|---|---|
| `services` | Defines the three containers: `dvwa`, `dvwa-db`, `juice-shop` |
| `depends_on` | Ensures `dvwa-db` starts before `dvwa` attempts to connect |
| `DB_SERVER=dvwa-db` | Tells DVWA to resolve its database host as `dvwa-db` (matches the container/service name — this is what allows DVWA's internal hostname `db` references to resolve correctly on the shared network) |
| `networks: lab-network` | Places all three containers on the same custom bridge network, so they can reach each other by service name |
| `restart: unless-stopped` | Containers automatically restart on VM reboot unless manually stopped |
| Ports | DVWA exposed on host port `8082`, Juice Shop on `3000`; `dvwa-db` has no published port (internal-only, accessed by other containers on the network, not from the host) |

Save and exit (`Ctrl+O`, Enter, `Ctrl+X` in `nano`).

## 6. Procedure — Deploying the Containers

### Step 6.1 — Start all services defined in the Compose file

```bash
docker compose up -d
```

The `-d` flag runs containers in detached (background) mode.

### Step 6.2 — Verify all three containers are running

```bash
docker compose ps
```

Or, using the standard Docker command:
```bash
docker ps
```

Expected: three entries — `dvwa`, `dvwa-db`, `juice-shop` — all with `Up` status.

### Step 6.3 — Access the applications

| Application | URL |
|---|---|
| DVWA | `http://localhost:8082` |
| Juice Shop | `http://localhost:3000` |

---

## 7. Ongoing Container Management

| Task | Command |
|---|---|
| Stop all containers | `docker compose stop` |
| Start all containers again | `docker compose start` |
| Stop and remove containers (keeps images) | `docker compose down` |
| Stop and remove containers + volumes | `docker compose down -v` |
| View logs for a specific container | `docker logs dvwa` |
| View logs (live/follow) | `docker logs -f dvwa` |
| Restart a single container | `docker restart dvwa` |
| Rebuild after editing the compose file | `docker compose up -d --build` |

## 8. Troubleshooting

### 8.1 DVWA shows a database connection error

**Symptom:** `mysqli_sql_exception: getaddrinfo for db failed`

**Cause:** `dvwa-db` is not running, or the two containers are not on the same Docker network.

**Resolution:**
```bash
docker compose restart dvwa-db
docker compose restart dvwa
```

### 8.2 Port already in use

**Symptom:** `Bind for 0.0.0.0:8082 failed: port is already allocated`

**Cause:** Another process or container is already using that port.

**Resolution:** Identify and stop the conflicting process, or change the host-side port mapping in `docker-compose.yml` (e.g. `"8083:80"`), then redeploy.

### 8.3 Docker command requires `sudo` unexpectedly

**Cause:** The current user session has not picked up the `docker` group membership yet (Step 3.6).

**Resolution:** Log out and back in, or reboot the VM.
